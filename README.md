# game-qa-playbook

游戏测试的方法论笔记。写给自己复盘，也给面试官看。

做了 14 个月游戏测试，两个项目：一款在研搜打撤端游的玩法模块、一款已上线 PVP 射击游戏的场景模块。这个仓库记的是**踩过的坑，以及踩完之后总结出来的判断规则**。不是工具教程，也不是面经。

> 仓库内所有案例、数据、表结构均为自造，不含公司资产、真实配置表、线上日志或未公开玩法。涉及项目只写到品类和模块粒度。

## 写法约定

每篇都按同一个结构，缺一段就算没写完：

1. **结论先行**。第一段把规则说完，不铺垫背景、不解释重要性。
2. **一个具体例子**。抽象规则谁都会写，值钱的是"在什么情况下这条规则会失效"。
3. **局限**。这套方法覆盖不了什么、需要谁补。写不出局限，说明还没真用过。

## 这个仓库对我自己有什么用

- 面试被追问"你怎么保证覆盖率"的时候，能打开一篇文档讲十分钟，而不是背概念。
- 换项目不用从零想，翻一遍就知道哪几类问题会先冒出来。
- 逼自己把"凭感觉"写成"有判据"。写着写着会发现有些事其实说不清，那些就是还没学会的部分。
