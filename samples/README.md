这些资产分别来自两个项目，哪些共有、哪些独有，见 [两个项目与资产归属](../PROJECTS.md)。简单说：01 和 04 在「场景」这一块（两个项目都有），02 和 03 只在搜打撤那边有。

## 为什么不直接放原始文件

三个理由，按重要性排：

1. **原始文件含未公开内容。** 我做的脱敏处理掉了人名、内网链接、需求号、版本代号、截图，但玩法机制、系统结构、数值口径本身还在。这些属于项目信息，不是我的个人作品，公开出去是越界。
2. **打开成本太高。** `.xmind` 需要装 XMind，`.xlsx` 要下载才能看。招聘方不会为了看一份作品集装软件。
3. **截图已被替换。** 脑图里的 63 张游戏截图在脱敏时全部重绘为灰块，图片证据本来就不在了，留下文件只剩树形文本——那用 Markdown 反而更清楚。

所以这里的做法是：**把结构、规模、判断依据写出来，把内容留在该留的地方。** 面试时我可以现场打开原始文件逐层讲。

## 命名与提交规范

这个仓库自己定的规则，写在前面，之后加东西照着来：

**目录**：`NN-主题/`，两位数字前缀保证排序，主题用小写英文短横线。中文只出现在文件内容里，不出现在路径——路径里的中文在 URL 里会被转义成一串 `%E5%9C%BA`，分享出去很难看。

**文件**：`kebab-case.md`。同一主题拆成「索引 + 分篇」，`README.md` 永远是那一层的索引。

**提交**：一个提交只做一件事，主题行写清楚改了什么，不加 `update`、`fix` 这种空词。

```
docs(scene): 补场景用例的字段结构与 4 条抽样
feat(weak-network): 增加提级标准矩阵
chore(samples): 统一目录前缀编号
```

**内容**：每篇都要有「规模」「结构」「局限」三个东西。只写"我做了什么"是简历，写清"做到什么程度、哪里没做到"才是作品。
