# 04 地图设计测试点

从地图设计文档翻译出来的测试点框架。原文讲"这张地图长什么样"，这一份讲"这样设计会怎么坏"。

不是用例清单。每一节列的是"要测什么"，展开成几条用例取决于地图规模和版本阶段。

## 规模

| 项 | 数量 |
|---|---|
| 章 | 9 |
| 节 | 23（前八章分节，第九章直接列三条） |
| 各章节数 | 4 / 3 / 2 / 3 / 2 / 4 / 3 / 2 / — |

原文是一份 6 页的 Word 设计文档，这份框架是逐节翻译的产物。**章节号和原文一一对应**，面试时可以拿原件对着看。

## 为什么要按这个顺序排

九章不是并列关系，是一条从"静态"到"动态"再到"组合"的推进：

| 段 | 章 | 在验什么 |
|---|---|---|
| 静态要素 | 一 POI、三 填充要素 | 地图上有什么，摆得对不对 |
| 通行 | 二 动线、四 出生点、五 撤离点 | 人怎么进来、怎么走、怎么出去 |
| 组合 | 六 交叉关联 | 前两段单独看都对，凑一起还对不对 |
| 整体 | 七 平衡、九 性能 | 玩一整局下来体验如何 |
| 兜底 | 八 异常边界 | 前面没想到的地方 |

**六章是整份框架的价值所在。** 一二三四五章谁都会列，交叉才需要真的跑过图：比如"三级 POI 多进多出"这条，没被堵死在点位里的人写不出来。

## 一份地图能直接用的三条判断

从这 23 节里挑出三条，是换个项目也成立的：

1. **核心 POI 的验收标准是"≥ 2 条联通路径"，不是"可达"。** 只有一条路就是单点卡位，被堵即死局。
2. **公平性要用数据验。** 跑 20 局记每个出生点到最近高价值点的距离，算方差，超过阈值就是设计问题。
3. **隐蔽动线必须真的更快或更隐蔽。** 如果绕远还安全，玩家不会走主动线，动线设计直接失效。

## 局限

- **阈值全部是示例值。** 500m、20%、30%、3–4 个撤离点来自单一项目，换项目不成立。能迁移的是"要验什么"和"为什么验"。
- **有撤离点，不代表这是搜打撤的样本。** 两个项目的地图里都有撤离点，三角洲同样要测位置、可达性、触发条件和同时撤离人数上限。这一章属于场景，不是归属依据；判断样本归谁看的是战斗判定体系（射击 / 魂类），见 [PROJECTS.md](../../PROJECTS.md)。
- **它是穷举框架，不带优先级。** 哪节先测要另叠一层：一四五章是基础（P0），六章是区分度（P0），七九章放版本后期。
- **不覆盖数值模型。** 资源产出总量、经济循环健康度要靠策划的数值模型，测试只能验"规则按配置执行"。
