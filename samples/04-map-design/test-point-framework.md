# 地图类玩法的测试点框架

针对战术竞技 / 生存探索类地图的测试拆解框架。九章，前八章分 23 节，第九章（性能与适配）没有再分小节，直接列三条。

核心目标：验证地图各构成要素的**功能性、合理性、平衡性、可玩性**，以及要素之间**交叉关联**是否成立。正向与反向都要覆盖。

用法：拿到一张新地图，按 1→9 顺序过一遍。每一节产出的是"要测什么"，不是"怎么测"——具体用例在模块用例库里。

## 一、POI 体系测试（核心基础要素）

POI（Point of Interest）是地图的骨架，按规模和功能分 1–4 级。

### 1.1 POI 分级测试（1–4 级）

- **视觉区分度**：四级 POI 是否规模最大、建筑最复杂、标识最醒目；一级是否确实"零散分布"
- **特征匹配**：主体建筑、控制室应匹配高等级 POI；附属小屋、哨点匹配低等级
- **可达性**：是否存在四级 POI 进不去、一级 POI 被地形完全挡住
- **分级与场景契合**：分级的逻辑要跟这张地图的叙事对得上，不能照搬另一张图的档位

### 1.2 POI 功能标签测试

- **标签准确性**："物资富集区""BOSS 刷新点""防御工事"无错标、漏标
- **交互有效性**：点击标签能否展开详情（等级、推荐人数、核心物资）
- **视觉优先级**：高等级标签是否比低等级更醒目，不被地形或 UI 遮挡

### 1.3 POI 间隔测试

- **实测间距**是否符合设计（示例阈值：四级 ≥ 500m，一级 ≤ 100m）
- **间隔合理性**：过密导致资源重叠，过散导致探索空窗期过长
- **地形适配**：平原、山地、水域周边的间隔要符合场景逻辑，不能一张表套全图

### 1.4 POI 联通关系测试

- **路径联通**：步行、攀爬、游泳、驾车四种方式下，从 A 到关联 B 是否都可达
- **路径合理性**：有没有"近路被堵""绕路过长"的设计缺陷
- **路径多样性**：核心 POI 是否有 ≥ 2 条联通路径
- **特殊联通**：上下层之间的楼梯、绳索、电梯是否可用

> 连通性是最容易出问题的一条。玩家不需要"有路可走"，需要"有两条路可走"——只有一条时会形成单点卡位，一旦被堵就是死局。

## 二、动线设计测试

### 2.1 动线流畅性测试

- **主动线**（核心 POI 间主干道）：无地形卡点、无穿模、无空气墙
- **次动线**（分支、隐蔽通道）：必须真的更快或更隐蔽，不能是"无效路径"
- **移动方式适配**：跑、蹲、攀爬、驾车各有通行限制（示例：爬坡角度 ≤ 45°）

### 2.2 动线与 POI 关联测试

- **覆盖**：不允许存在"无任何动线可达"的孤立 POI
- **辐射范围**：四级 POI 是否有 ≥ 3 条动线向外延伸
- **风险-收益匹配**：隐蔽动线对应低暴露，主动线对应高遭遇——如果隐蔽路线反而更快更安全，动线设计就失效了

### 2.3 动线地形适配测试

- **特色地形动线**：斜坡、泄洪道、桥梁等，验通行安全性（坠落、卡顿）
- **障碍与动线协调**：河流、悬崖、围墙应引导动线，不能造成"强制绕路"

## 三、填充要素测试（容器、怪物）

### 3.1 容器测试

- **数量与 POI 级别**：四级 > 三级 > 二级 > 一级，符合设计比例
- **产出与级别对应**：高等级 POI 出高价值物资，不允许反向
- **刷新规则**：间隔、数量稳定，无"零物资容器"、无"重复刷新"
- **交互可用性**：打开/拾取流畅，无打不开、拾取后物资不消失

### 3.2 怪物测试

- **分布与 POI 级别**：四级刷精英/BOSS，一级只刷普通怪
- **强度与风险平衡**：血量、伤害、攻击频率要与产出价值匹配
- **AI 合理性**：会追击、会躲、会用地形，无原地不动、穿模攻击、无限回血
- **与容器绑定**：BOSS 守护的容器必须在 BOSS 被击败后解锁
- **刷新规则**：无"刷怪过多导致卡死"、无"长期不刷怪"

## 四、出生点测试

### 4.1 出生点位置选择测试

- **分布**：均匀分布在地图边缘或安全区，不集中在单一区域
- **公平性**：所有出生点到最近四级 POI 的距离差异 ≤ 20%（示例阈值）
- **安全性**：不落在陷阱、初始怪物、不可移动模型里
- **场景契合**：避开泄洪口、悬崖这类危险地形

### 4.2 出生点随机规则测试

- **随机公平**：多次开局后各点被选中概率均衡，不存在"某点永不刷新"
- **队伍间距**：不同队伍保持安全距离（示例 ≥ 300m），无"开局即相遇"
- **容错**：部分出生点不可用时能自动切备用点

### 4.3 出生点队伍数量适配测试

- **分配**：10 队、20 队等配置下，每队有独立出生点，无重叠
- **上限匹配**：最大队伍数 ≤ 出生点总数

> 公平性这一条要用数据验，不能靠感觉。做法是跑 20 局记录每个出生点到最近高价值点的距离，算方差。差异超过阈值就是设计问题，不是 bug——但测试要把它指出来。

## 五、撤离点测试

### 5.1 撤离点位置与可达性测试

- **分布**：覆盖东、西、南、北不同方位，不集中在一个方向
- **距离**：到四级 POI 的距离适中——太近无风险，太远到不了
- **可达性**：至少一条主动线可达，不被地形或怪物完全封锁
- **场景契合**：码头、闸门、直升机平台这类位置才立得住

### 5.2 撤离点功能测试

- **触发条件**：倒计时、激活开关等是否正常生效
- **过程流畅**：有动画与提示，无卡顿、闪退、无法完成
- **安全性**：有防御空间，不出现"刚到即被秒"
- **数量适配**：队伍数与撤离点数量匹配（示例：10 队对应 3–4 个），避免拥堵

## 六、要素交叉关联测试（核心）

这一节是整份框架的重点。前面五节各自都能过，交叉起来照样出问题。

### 6.1 POI 与动线 / 联通关系交叉

- 三、四级 POI 要"多进多出"，不能易进难出
- 一级 POI 路径要简洁，不能绕路到没有探索价值

### 6.2 出生点 → POI → 撤离点交叉

- 任意三点之间的动线连贯，无必经卡点
- 不同出生点到撤离点的总距离差异 ≤ 30%（示例阈值）

### 6.3 容器 → 怪物 → POI 级别交叉

- 高等级 POI 击败精英后必出高价值物资
- 不允许"弱怪守神装"或"强怪守垃圾"

### 6.4 动线 → 怪物交叉

- 主动线怪物密度不能高到堵塞动线
- 次动线要符合"隐蔽路径低风险"

## 七、整体平衡性与可玩性测试

### 7.1 资源分布平衡性

- **均匀性**：各级物资在全图分布均匀，无局部过剩或匮乏
- **获取难度**：高价值物资必须对应高风险，无"轻松拿神装"

### 7.2 对局节奏平衡性

- **整体时长**：出生 → 探索 → 撤离符合设计（示例：20–30 分钟），无过长空窗或来不及撤离
- **成长曲线**：前期怪物可被基础装备击败，后期 BOSS 需要配合

### 7.3 可玩性测试

- **战术多样性**：支持刚枪、偷袭、苟分撤离等不同打法，不能存在单一最优解
- **场景互动**：闸门、电梯、桥梁等可交互且能用于战术（关门阻挡追兵）

## 八、异常场景与边界测试

### 8.1 功能异常测试

- **POI**：进入后模型消失、无法退出、被空气墙挡住
- **容器**：打不开、拾取后背包不显示、物资重复刷新
- **怪物**：穿模、无限攻击、不刷新、无法击败
- **出生/撤离**：出生在地形外、撤离点无法触发、撤离后掉线或直接死亡

### 8.2 边界条件测试

- **数量边界**：最大/最小队伍数下的出生点分配、刷怪、撤离点承载
- **移动边界**：地图边缘阻挡是否闭合，无"走出地图"、"卡进地形缝隙"
- **时间边界**：倒计时结束后未撤离的判定，无"无限存活"

## 九、性能与适配测试

- **加载**：进入地图 ≤ 3s，无卡顿黑屏
- **渲染**：POI 密集区、战斗场景帧率 ≥ 60fps，无掉帧闪退
- **多端**：手机、平板、PC 的 POI 显示、动线操作、怪物交互是否一致

## 这份框架的局限

**它是一份"穷举式"框架，不是"优先级排序"。** 九章平铺，看不出哪节该先测。实际执行时必须叠一层优先级：一、四、五章是地图能不能玩的基础（P0），六章是区分度所在（P0），七、九章通常放到版本后期（P1/P2）。

**阈值全部是示例值。** 500m、20%、30%、3–4 个撤离点这些数字来自单一项目，换个项目就不成立。**能迁移的是"要验什么"和"为什么验"，不是数字。**

**它不覆盖数值模型。** 资源产出总量、经济循环是否健康，需要策划的数值模型配合，测试只能验证"规则按配置执行"。

**交叉章节的深度不齐。** 6.1 和 6.4 各只有两条，是因为实际项目里这两处暴露的问题最少——不是设计得简略，是没写那么多。补全的代价要先评估问题密度，不要为了对称硬凑。
